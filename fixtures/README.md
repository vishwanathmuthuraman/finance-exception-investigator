# Original synthetic fixtures

Eight hand-authored development bundles; no real person, company, bank or customer record is represented. [Manifest](manifest.json) links inputs to separate evaluator-only expected outcomes.

| Bundle | Expected rules outcome | Meaning |
|---|---|---|
| clean-settled | clear | USD 100 invoice, payment and ledger agree. |
| clean-partial | clear | USD 60 outstanding; invoice is not yet due. |
| duplicate-invoice | review_required | Repeated supplier invoice number; no arbitrary duplicate selection. |
| amount-mismatch | review_required | Invoice ledger understates the invoice by USD 5. |
| overdue-partial | review_required | USD 60 outstanding after the due date. |
| missing-ledger | insufficient_evidence | Payment exists but its payment ledger entry is absent. |
| missing-invoice | insufficient_evidence | Payment/ledger reference an absent invoice. |
| clean-two-payments | clear | USD 40 and USD 60 payments settle a USD 100 invoice. |

Amounts are cents; all bundles use USD and an as-of date of 2026-01-31. JSON source pointers resolve within the named input file. Records use IDs unique within their bundle.

The [CSV directory](csv/clean-settled/orders.csv) contains four alternative input files for clean-settled, not an additional benchmark case. Blank optional references map to null; integer/date parsing must be strict. CSV row provenance is generated by the future importer.

Expected outcomes describe **rules semantics**, not actual system runs. Exact matching may abstain on cases needing aggregation or duplicate analysis; record that difference rather than rewriting the oracle. Expected links include only unambiguous links. Expected findings are required findings, not an instruction to suppress valid secondary effects; score primary categories separately. A missing-record finding cites the observed reference; absence is checked against the whole bounded bundle.

These seeds occupy 8 of the planned 40 development positions: 3 clean and 5 exception.
